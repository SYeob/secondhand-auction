# Postman 핵심 입찰 TC 매핑

상태: **구현 완료 / 실제 서버 미실행**. 기존 Python 회귀 결과 23 PASS / 1 XFAIL과 별개입니다.

## 공통 사전 조건

- 활성 Supabase 테스트 환경, 유효한 공개 API 키.
- 이메일 인증을 마친 판매자·입찰자 A·입찰자 B의 서로 다른 계정 3개.
- 각 입력 조건마다 별도 상품을 생성: 시작가·현재가 10,000원, 종료 시각은 생성 시점에서 24시간 이후.
- 종료 상태는 해당 TC에서만 과거 시각으로 수정.
- ID와 금액은 UI 문구가 아니라 서버 응답 및 REST 재조회로 검증.

오류 판정은 저장소의 SQL 트리거·NOT NULL·RLS와 기존 클라이언트 구성을 기준으로 작성했습니다. 배포 버전의 명세가 달라졌다면 기대 결과를 검토한 뒤 문서와 스크립트를 함께 수정합니다. 실패를 통과시키기 위해 임의의 4xx·5xx를 모두 허용하지 않습니다. 5xx·네트워크 실패는 기대한 입찰 거부로 인정하지 않습니다.

## 종료와 판정

각 폴더는 생성 상품을 판매자 토큰으로 삭제하고 상품과 입찰 내역이 빈 배열인지 확인합니다. 모든 준비·검증·정리가 완료되고 모든 필수 요청이 실행된 경우에만 마지막 종합 assertion을 PASS로 판정합니다. 개별 HTTP 성공 또는 일부 assertion 성공은 TC 전체 PASS가 아닙니다.

구현한 TC는 8개이며 TC-BID-002의 두 입력을 별도 실행하므로 입력 조건별 실행은 9개입니다. Postman assertion 수·요청 수·TC 수를 혼동하지 않습니다.
